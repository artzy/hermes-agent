# Hermes — 여러 작업 폴더에 걸쳐 작업하는 방법

작성: 2026-07-29  
대상: hermes-agent (Profiles / Projects / cwd 모델)

## 전제 (왜 “한 번에 여러 폴더”가 안 되나)

Hermes 세션은 **하나의 주 작업 디렉터리(cwd)** 를 기준으로 돌아간다.

| 표면 | cwd 결정 |
|------|----------|
| CLI / TUI | 프로세스 시작 디렉터리 (`os.getcwd()`), 또는 `terminal.cwd` |
| Messaging gateway | `config.yaml`의 `terminal.cwd` → `TERMINAL_CWD` |
| Desktop | Project의 **primary** 폴더 (새 세션 cwd) |
| Cron | 기본은 gateway cwd, 선택적으로 job `workdir` |

이 cwd에서 `AGENTS.md` / `.cursorrules` 등이 로드되고, coding workspace 스냅샷·LSP·체크포인트도 여기에 묶인다.  
VS Code식 **multi-root workspace를 한 세션에 동시에 붙이는 모델은 의도적으로 없다.**

Profile ≠ workspace:

- **Profile** = Hermes 상태 섬 (`config`, `.env`, memory, sessions…)
- **Workspace/cwd** = 터미널·파일 도구 시작 위치 (`terminal.cwd`)
- Profile은 샌드박스가 아님 — local 백엔드면 다른 절대경로도 읽을 수 있음

## 권장 전략 (상황별)

### 1) 관련 있는 여러 폴더/레포를 “한 작업 단위”로 (가장 권장)

**First-class Project** 사용.

```powershell
hermes project create my-app --folder D:\work\frontend
hermes project add-folder my-app D:\work\backend
hermes project set-primary my-app D:\work\frontend
hermes project use my-app
```

- 상태: `$HERMES_HOME/projects.db` (프로필별)
- **primary** = 새 세션의 cwd / Desktop 사이드바 앵커
- 추가 폴더는 프로젝트 멤버십·세션 그룹핑에 쓰임
- Desktop: Sidebar → Projects (권장 UI). GUI 세션에는 `project_list` / `project_create` / `project_switch` 도구가 붙음
- Kanban board와 `hermes project bind-board`로 묶으면 worktree/브랜치 규칙이 프로젝트 primary에 고정됨

**한 세션 안에서의 교차 폴더 작업:**  
primary에서 시작하되, 도구에 **절대 경로** 또는 `terminal(..., workdir="D:\work\backend")` 로 다른 멤버 폴더를 건드린다.  
(CLI에서는 Project가 cwd를 자동 강제하지 않으므로, Desktop을 쓰거나 해당 폴더에서 `hermes`를 띄우거나 `terminal.cwd`를 맞춘다.)

### 2) 성격이 다른 프로젝트 / 봇을 완전히 분리

**Profile + `terminal.cwd`.**

```yaml
# ~/.hermes/profiles/coder/config.yaml
terminal:
  backend: local
  cwd: D:/GitHub/AI/hermes-agent
```

```powershell
hermes profile create coder --clone
coder config set terminal.cwd D:/path/to/repo   # 또는 YAML 직접 편집
coder chat
```

메모리·세션·스킬·게이트웨이가 섞이지 않는다.  
“여러 폴더를 한 대화에서”가 아니라 “폴더마다 에이전트 인스턴스”에 가깝다.

### 3) CLI만 쓸 때 (Project UI 없이)

- **폴더별로 세션을 연다:** 해당 프로젝트 루트에서 `hermes` / `hermes --tui` 실행 (`cwd: "."`면 시작 디렉터리 = 프로젝트).
- 각 루트에 `AGENTS.md`를 둔다.
- 한 대화에서 잠깐 다른 트리를 봐야 하면 절대경로 / `workdir=` — 단, **컨텍스트 파일은 시작 cwd 기준**이므로 장기 작업은 폴더별로 세션을 나누는 편이 낫다.

### 4) 병렬·장기·역할 분담

- **Kanban** + 여러 profile (워커별 역할 / board / tenant)
- **Cron** job에 `workdir=` (해당 job만 그 레포에서 실행; workdir job은 틱당 직렬)

## 한 줄 결론

| 목표 | 최선의 방법 |
|------|-------------|
| 연관 레포 여러 개를 하나의 작업 공간으로 | `hermes project` (+ Desktop Projects) |
| 완전 격리된 에이전트/설정 | Profile + `terminal.cwd` |
| 가끔 다른 경로만 건드리기 | 같은 세션에서 절대경로 / `workdir` |
| 스케줄·멀티에이전트 | Cron `workdir` / Kanban |

**가장 좋은 기본값:** 관련 폴더는 Project로 묶고 primary를 정한 뒤 Desktop(또는 그 primary에서 CLI)에서 작업하고, 무관한 프로젝트는 Profile로 분리한다.

## Windows: `hermes.bat` 멀티폴더 런처

`hermes.bat`는 기동 시 폴더 목록을 읽어 Hermes Project(`local-workspace`)에 sync한 뒤 primary로 `cd`한다.

```text
HERMES_WORKDIRS / %HERMES_HOME%\workdirs / hermes.workdirs / HERMES_DEFAULT_WORKDIRS
```

자세한 설정·검증: `Analysis/hermes-bat-초기-작업디렉토리.md`
